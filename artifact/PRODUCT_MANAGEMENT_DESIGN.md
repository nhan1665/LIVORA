**Target Platform:** LIVORA Admin Web Application (Angular 19 Standalone, TypeScript, RxJS)  
**Author / Team:** LIVORA Engineering Pair Programming Assistant  
**Date:** October 2026  
**Status:** Approved for Implementation / Implemented

## 1. Executive Summary & Module Scope

The **Product Management** module serves as the primary merchandising and catalog operations hub in the LIVORA furniture e-commerce ecosystem. It empowers administrators to configure multi-tier product categories, catalog items, pricing, inventory thresholds, specifications, multi-room associations, and 3D Augmented Reality (`.glb`) assets.

### Assigned Scope:
1. **Category Management (`/products/categories`):**
   - Summary and counts of operational vs. paused categories.
   - Search by category business code, display name, and SEO slug.
   - Operational status filtering (`Đang hoạt động` vs. `Tạm dừng`).
   - Pagination (10 categories per page, 14 seeded initial categories).
   - Create Category Dialog (`Popup thêm mới loại sản phẩm`): code, name, slug, display order, operational status, description.
   - Edit Category Dialog with prefilled data and validation.
   - In-place operational status toggle and deletion.

2. **Product Catalog Management (`/products/list`):**
   - KPI Summary Cards: Total products (348), Active in business (312), Out of stock (24), 3D AR Models available (86).
   - Advanced Search & Filtering: Search keyword (name, SKU, materials), category selector, operational status selector, stock status selector, 3D AR filter (`Có file .GLB` vs. `Chưa có file`), and sorting (Newest, Price asc/desc, Stock asc/desc).
   - Responsive Catalog Table: Thumbnail, title, SKU pill, room pills, category tag, retail & promotional pricing, inventory count, stock status badge, 3D AR status badge, operational status toggle button, and quick actions.
   - Pagination: 10 items per page across 35 pages (348 items).
   - Create Product Dialog (`Popup thêm mới sản phẩm`): Multi-tab layout (1. General & Pricing; 2. Specifications & Dimensions; 3. Media & 3D AR Model).
   - Edit Product Dialog: Full synchronization with draft model and optimistic local update.
   - Operational status toggle and deletion.

## 4. Database Anomalies & Architectural Recommendations for Thuan Cao

The following architectural anomalies were identified during DB inspection and must be escalated to **Thuan Cao**:

### Anomaly 1: Missing 3D Model Field in Table 19 (`Products`)
- **Observation:** Both the Figma design reference (`Quản lý sản phẩm - Quản lý danh sách sản phẩm - LIVORA Admin.png`) and user requirements prominently feature a column `MÔ HÌNH 3D AR (.GLB)` (`Có file .GLB` / `— Chưa có`) and a creation popup input for uploading or linking `.glb` files. However, Table 19 (`Products`) in `REPORT.docx` does not define any field for 3D assets (e.g., `file3DUrl`, `model3DUrl`, or `glbUrl`).
- **Contrast:** Table 21 (`RoomDesigns`) explicitly defined `file3DUrl: String` ("Đường dẫn tải tệp mô hình không gian 3D (định dạng tệp .glb)").
- **Solution Implemented in Admin:** Added optional `file3DUrl?: string` and derived `has3DModel: boolean` to `ProductItem` and `ProductDraft` so that the AR merchandising feature functions smoothly.
- **Recommendation for Thuan Cao:** Add `file3DUrl: String` to Table 19 `Products` in the official MongoDB schema documentation.

### Anomaly 2: Dual Status Fields in Table 19 (`Products`)
- **Observation:** Table 19 specifies both `stockStatus` (`"in_stock" | "out_of_stock"`) and `status` (`"Đang kinh doanh" | "ngưng kinh doanh"`).
- **Business Distinction:** In production e-commerce, stock availability (`stockStatus`) is dynamically driven by warehouse inventory (`stockQuantity > 0 ? 'in_stock' : 'out_of_stock'`), while business status (`status`) is an administrative operational toggle controlling storefront visibility.
- **Solution Implemented in Admin:** Filter toolbar supports filtering by operational status as well as inventory status, while the table toggle button controls `status` (`Đang kinh doanh` vs `ngưng kinh doanh`).

### Anomaly 3: Table 17 (`Categories`) Missing Business Display Code
- **Observation:** Figma category list displays a prominent `MÃ LOẠI` column (e.g., `CAT-SOFA`, `CAT-TABLE`, `CAT-CHAIR`, `CAT-BED`), but Table 17 only has `_id`, `name`, `slug`, `parentId`, `description`, `thumbnail`, `displayOrder`, and `isActive`.
- **Solution Implemented in Admin:** Added `code: string` to `ProductCategory` and the category creation/editing modal.
- **Recommendation for Thuan Cao:** Add `code: String (Unique)` to Table 17 `Categories`.

### Anomaly 4: Table 17 Missing Thumbnail Field in Figma Popup
- **Observation:** Table 17 defines `thumbnail: String`, but the Figma popup `Thêm mới loại sản phẩm` only contains code, name, slug, order, status, and description.
- **Solution Implemented in Admin:** Form accepts code, name, slug, order, status, and description while assigning a default thumbnail automatically if not supplied.

### Anomaly 5: Table 15 (`Customers`) Missing Account Type and Business Code
- **Observation:** Table 15 does not declare `customerType` ("registered" vs "guest") or `code` (`#270926-001`), even though Section 3.3.2.8 BPMN specifies handling guest vs registered customers (guest orders have null `passwordHash`).
- **Solution Implemented in Admin:** Preserved `customerType` and `code` as first-class domain properties in `CustomerRecord`.

## 5. Component Architecture & Style Budget Optimization

### 5.1 Architecture
- **Standalone Components:** `Category` (`app-category`) and `Product` (`app-product`) are Angular 19 standalone components using Angular Signals (`signal()`) for deterministic reactive change detection.
- **Separation of Concerns:** 
  - `category.model.ts` & `product.model.ts`: Pure TypeScript domain contracts.
  - `category.service.ts` & `product.service.ts`: Injectable singleton services managing state via RxJS `BehaviorSubject` and returning typed Observables.
  - `category.ts` & `product.ts`: Presentation logic, filtering, sorting, pagination, and modal state.
  - `category.html` & `product.html`: Clean accessible markup with semantic tables, SVG icons, and responsive dialogs.
- **Budget Limit Compliance (`anyComponentStyle`):** Angular CLI enforces an 8 kB style budget for component styles in `angular.json`. Declaring extensive table and modal CSS in `styleUrl` triggers compile-time budget errors. Therefore, all module styles are scoped to custom element tags (`app-category`, `app-product`) in `category.css` and `product.css` and imported globally in `src/styles.css`.
